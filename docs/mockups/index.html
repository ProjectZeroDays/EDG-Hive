Design direction — what changes and why

The current UI is a competent operator console: flat light theme, card lists, per-feature pages. To reach enterprise grade we keep the information architecture (it is already close to how security teams think: engagements → findings → evidence) and add the four things enterprise buyers require: command-level situational awareness, governed action (RBAC + approvals + audit), workflow (triage → retest → report), and scale (multi-tenant, fleets of agents).

A
Keep

Sidebar IA · exploration graph as first-class object · evidence-linked findings · chat-first steering · per-task tabs (Overview/Findings/Retest/Report). All enterprise features hang off this skeleton instead of replacing it.

B
Elevate

Command dashboard becomes the home page · global command palette (⌘K) · saved views & filters everywhere · density modes · dark SOC theme · breadcrumbs + context header on every screen.

C
Add

Tenancy & RBAC, SSO/SCIM, immutable audit trail, findings triage board with SLAs, approval center with risk scores & dual-control, traffic workbench with diff/replay, report builder, integrations, fleet & cost analytics.

    D · Dashboard features

  • D1–D5 KPI strip: cross-engagement posture at a glance; every tile deep-links; per-role configurable widget layout.
  • D6 Risk trend: severity-weighted exposure over time with annotations (patch windows, retests) — the board-level metric.

    W · Workspace features

  • W1 Graph v2: layouts (hierarchical/radial/timeline), minimap, outcome coloring, node pinning, “why this node” one-click — built on the existing G6/xyflow stack.
  • W2 Inspector: every node has rationale, route, evidence chips, cost. Turns the graph into an audit artifact.
  • W3 Steering: hints inject into planner + worker context with delivery receipts.
  • W4 Side questions: batched inbox with risk-labeled options; answers recorded in the graph.
  • W5 Run diff: compare two runs on the same scope — coverage delta, new/closed findings, regressions.
  • W6 Run control: live pace/egress/budget knobs; auto-pause policies.
  • W7 ⌘K palette: global navigation + actions (“approve latest”, “link flow to finding”).
  • W8 Context meter: per-agent context usage with compaction warnings — uses the sidequestion/context package that already exists.

    F · Findings features

  • F1 Saved views: shareable filter sets per user/role; default board per engagement.
  • F2 Board: drag-and-drop lifecycle; WIP hints; keyboard-first triage (J/K to move, A to assign).
  • F3 Dedup engine: asset + weakness fingerprinting suggests merges; keeps history.
  • F4 Tracker sync: two-way Jira/GitHub/ServiceNow with status mirroring and failure badges.
  • F5 Retest windows: schedule verification into customer maintenance windows; auto-verify with evidence diff.
  • F6 Detail drawer: CVSS 4.0 calculator, ATT&CK mapping, blast-radius rollup, attack-chain view from the exploration graph.
  • F7 One-click retest: spins the existing retester agent against saved evidence context.
  • F8 Dual control: “accept risk” and severity-downgrade require a second approver; enforced server-side.

    A · Guardrail features

  • A1 Explainable blocks: judge reasons rendered as sentences with matched signatures and historical context.
  • A2 argv diff: proposed command vs policy baseline with the flagged tokens highlighted.
  • A3 Decision verbs: once / pin / modify / deny — pins feed the existing intercept pin store.
  • A4 Immutable trail: hash-chained events; streamed to SIEM; shown inline per request.
  • A5 Policy presets: Paranoid / Balanced / Aggressive / Custom — versioned, per-engagement overridable.
  • A6 Guarded bulk: bulk-approve bounded by count and risk ceiling; always logged individually.
  • A7 Break-glass: time-boxed unguard with strong auth and mandatory reason.

    T · Traffic features

  • T1 Search: full-text across URL/headers/body/meta with saved searches and alerting (“notify me on 5xx on /pay”).
  • T2 Split panes: request/response with highlighting for matched signatures, auth material, and evidence links.
  • T3 Diff: two-flow or baseline-vs-tamper comparison to prove impact without leaving the tool.
  • T4 Replay: resend any flow to the same or a staging target through the existing rewrite/replay engine.
  • T5 Annotation: comments + highlights become structured finding evidence with chain-of-custody hashes.
  • T6 Redaction lens: togglable PII masking for screen-sharing/review mode (uses the existing Redact config).
  • T7 Flow compare: before/after patch, or cross-run regression proof.

    G · Governance features

  • G1 Tenancy: org → tenant → engagement hierarchy; per-tenant keys, quotas, retention, data residency.
  • G2 RBAC matrix: five built-in roles, custom roles; enforced in the Go mux, not just hidden in UI.
  • G3 JIT elevation: time-boxed privilege grants with approver + reason — replaces shared admin accounts.
  • G4 Scoped API keys: per-key permissions and rotation policy; first-class UI + usage stats.
  • G5 Immutable audit: hash-chained events for every mutation; chain verification + SIEM streaming.
  • G6 LLM pool health: existing health engine visualized with spend and per-task budget burn-down.
  • G7 Cost governance: monthly budgets, per-engagement caps, anomaly alerts on spend rate.
  • G8 Residency & retention: tenant-level policy for storage, crypto keys, and evidence lifetime.
